```c

void f1(pila_t* pila)
{
    while (!pila_vacia(pila))//O(n)  //pila_vacia(pila) -> O(1)
        pila_quitar(pila);//??
}


```

Para poder resolver el problema de calcular la complejidad computacional , tendriamos que hacer algunas suposiciones ya que no sabamos como estan implemenetadas las funciones que se llaman. Teniendo en cuenta esto, paso a calcular:

- `while(!pila_vacia(pila))` : Como no sabemos el tamaño exacto de la pila , suponemos que este bucle `while()` se va a ejecutar `n` veces. O(n)

- `!pila_vacia(pila)`: esta funcion suponemos que solo verifica si hay algo en la pila, o si esta vacia; por lo tanto seria O(1).

- `pila_quitar(pila)`: en esta funcion tambien suponemos la implementacion y que sea una implementacion constante, si quitar un elemento de la pila es una operacion constante entonces suponemos que es O(1)

Habiendo analizado lo anterior , la funcion `f1` tendria una comlejidad total de O(n)

```c

int f2(int n)
{
    int k=0;  //O(1)

    for (int i=0; i<n; i++) {  //O(n)
        for (int j=0;j<n;j++) { //O(n)
            if (j==10) //O(1)
                i++; //O(1)
            k++; //O(1)
        }
    }

    return k; O(1)
}

```

En este caso de codigo , y calculando la complejidad en el peor caso, podemos observar que en la funcion `f2`, las operacion de asignacion, incrementos y el condicional if() son O(1). El problema se presenta a la hora de calcular los ciclos for(), podrimos decir que tenemos un ciclo exterior (`for (int i=0; i<n; i++) `) y uno interior (`for(int j=0;j<n;j++)`).
En el caso del ciclo exterior a simple vista podemos asumir que se ejecuta desde 0 hasta n iteraciones, lo mismo pasa con el ciclo interior, pero tenemos un condicional que indica que si `j` es igual a `10`, `i` se incrementa por lo que se "saltaria" una iteracion del ciclo exterior.
A pesar de esto, en el peor caso no cambia la complejidad de tener dos ciclos anidados y la complejidad seria O(n^2).
